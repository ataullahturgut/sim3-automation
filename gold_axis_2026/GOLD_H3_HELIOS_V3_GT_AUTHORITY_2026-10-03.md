## 1. Scientific purpose

HELIOS V1/V2 solved the macro problem: whether the reversal layer is competent enough to be allowed to act.
V3-GT addresses the unresolved micro problem: when the HELIOS macro gate is ACTIVE, which individual OPAL reversal events deserve a flip.

The architecture is:

`AURORA -> HELIOS macro gate -> OPAL candidate pool -> online policy market -> FLIP / KEEP AURORA`.

This is a retrospective strengthening study. It is not prospective confirmation and cannot replace the frozen AURORA champion.

## 2. Frozen macro gate

V3-GT inherits the exact HELIOS V1/V2 macro gate without retuning:
- latest 8 matured HELIOS consensus-candidate outcomes;
- initial INACTIVE;
- enter ACTIVE at >=5 wins of 8;
- exit ACTIVE at <=3 wins of 8;
- hold state otherwise;
- target outcome must be mature before use.

V3-GT may never route a reversal while this macro gate is INACTIVE.

## 3. OPAL event pool and information freshness

The micro arbiter evaluates every frozen OPAL override while the macro gate is ACTIVE.

For each OPAL event, the CFTC report vintage already available at the forecast origin is carried from the frozen OPAL ledger.
`COT_FRESH=1` only for the first OPAL override generated by that report vintage.
Repeated calls from the same COT report are treated as repeated use of the same information, not independent new evidence.

No future COT report, target return, target direction, or unmatured event outcome may enter the decision.

## 4. Binding game-theoretic policy market

Binding policy set:
1. `KEEP`: never flip.
2. `HELIOS_CONSENSUS`: flip only when the frozen HELIOS consensus candidate is present.
3. `COT_FRESH`: flip only on the first OPAL override from a COT report vintage.
4. `FRESH_OR_CONSENSUS`: flip when either COT_FRESH or HELIOS_CONSENSUS is true.
5. `OPAL_ALL`: flip every OPAL override.

Each policy has action `a_i,t in {0,1}`, where 1 means FLIP.

Binding utility on a matured OPAL event:
- rescue: +1 if the policy voted FLIP;
- broken: -1 if the policy voted FLIP;
- KEEP action: 0.

Only the latest **8 matured OPAL events** enter the binding policy-game score.

For policy i:

`U_i,t = sum recent utility_i`

`eta = sqrt(8 * log(K) / 8)`

`w_i,t proportional exp(eta * U_i,t)`.

The game-market flip share is:

`S_t = sum_i w_i,t * a_i,t / sum_i w_i,t`.

Binding event decision:
- macro gate must be ACTIVE;
- OPAL override must exist;
- `S_t > 0.50`.

Otherwise keep AURORA.
